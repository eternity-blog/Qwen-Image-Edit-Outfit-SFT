## 0. 一分钟讲清这个项目

```
VITON-HD 公开数据
      │
      ├─ IDM-VTON（单任务 try-on 专家）批量生成「人穿 B」目标图
      │        ↓  这一步是数据蒸馏：把专家能力变成 (输入,目标) 对
```

能吃多图的通用编辑模型，然后用留出集 + 配对检验判断训练方式与数据规模的真实收益。

## 1. 扩散模型基础

### 1.1 它在学什么

扩散模型学的是**如何从噪声一步步走回数据**。训练时不是让模型直接输出图片，而是：

1. 取一张真图 $x_0$
2. 随机采一个时刻 $t$，按 schedule 把它和噪声混合成 $x_t$
3. 让模型看着 $x_t$（以及条件）预测「该往哪走」
4. 与真实答案做回归损失

**关键点：每一步训练只看一个随机 $t$、一份随机噪声。** 这直接决定了训练 loss 是噪声主导的量
（见第 10.7 节，这是本项目一个重要实测结论）。

### 1.2 三种预测目标

| 参数化 | 模型输出 | 代表 |
|---|---|---|
| $\epsilon$-prediction | 预测加进去的噪声 | DDPM |
| $v$-prediction | 预测速度（噪声与数据的组合） | Imagen、部分 SD |
| **Flow Matching** | 预测从噪声到数据的**速度场** | SD3、FLUX、**Qwen-Image 系** |

**【配置】** 本项目底座用 `FlowMatchEulerDiscreteScheduler`，`num_train_timesteps=1000`。

### 1.3 Flow Matching 直觉

经典 DDPM 定义了一条带随机性的马尔可夫链；Flow Matching 直接定义**噪声与数据之间的直线插值路径**：

$$x_t = (1-t)\,x_0 + t\,\epsilon$$

真实速度就是常量 $\frac{dx_t}{dt} = \epsilon - x_0$，模型学着预测它。推理时从纯噪声出发，
用 Euler 等积分器沿速度场积分回去。

**为什么现代模型偏好它**：路径更直 → 需要的积分步数更少 → 采样更快；训练目标也更简洁
（不需要复杂的 noise schedule 推导）。

### 1.4 【配置】动态时间步偏移（dynamic shifting）

scheduler 里有 `use_dynamic_shifting=true`、`base_image_seq_len=256`、`max_image_seq_len=8192`、
`base_shift=0.5`、`max_shift=0.9`。

含义：**图像分辨率越高（token 越多），噪声 schedule 越要往高噪声端偏移**。
因为高分辨率图的低频结构需要在更多步里被确定。这也是为什么改分辨率不是无害的——
它会改变实际训练到的噪声分布。

### 1.5 常见追问：这和 LLM 的 SFT 有什么不同

| | LLM SFT | 扩散编辑 SFT |
|---|---|---|
| 损失 | 交叉熵，next-token 预测 | 回归损失（MSE 类），预测速度/噪声 |
| 监督粒度 | 每个 token 一个标签 | 整张图一个目标，但被 $t$ 随机化 |
| 一步训练看到 | 完整序列 | 一个随机时刻的中间状态 |
| loss 可读性 | 相对稳定，可看趋势 | **噪声主导**，单步不可信 |

面试常见坑：把「SFT」理解成只有 next-token 那一种。这里的 SFT 指的是「有监督微调」这个泛称，
损失形式完全不同。

## 2. 架构：VAE / DiT / Text Encoder

### 2.1 三件套

```
Text Encoder (Qwen2.5-VL, ≈8.29B)   文本 + 条件图 → 语义表示
VAE          (≈0.13B)               像素 ↔ latent，空间 8× 下采样
DiT          (≈20.43B)              条件生成主干  ← 本项目训练的就是它
```

**【实验】** 三者 bf16 权重合计约 57.7GB（DiT 40.86GB + TE 16.58GB + VAE 0.25GB），
这个数字决定了单卡能不能整卡装下（80GB 卡可以，但余量不多）。

### 2.2 为什么在 latent 空间做扩散

直接在 1024×1024×3 像素上做扩散，token 数会爆炸。VAE 先把图压到 latent：

**【配置】** `z_dim=16`，`dim_mult=[1,2,4,4]` → 空间 8× 下采样。
所以 1024×1024 图 → 128×128×16 latent。

再经 DiT 的 patchify（`patch_size=2`）→ 64×64=4096 个 token，每个 token 维度
$16 \times 2 \times 2 = 64$（正好对应 `in_channels=64`）。

**这就是「latent diffusion」的核心动机**：把序列长度从百万级降到千级。

### 2.3 DiT vs UNet

| | UNet（SD1.5/SDXL） | DiT（SD3/FLUX/Qwen-Image） |
|---|---|---|
| 主干 | 卷积 + 下采样/上采样 + skip | 纯 Transformer block 堆叠 |
| 条件注入 | cross-attention 到文本 | **joint/双流 attention**，图文 token 拼在一起 |
| 分辨率适应 | 受卷积结构限制 | 靠位置编码，天然更灵活 |
| Scaling | 较难 | 遵循 Transformer scaling law，好扩 |

**【配置】** 本项目 DiT：`num_layers=60`，`num_attention_heads=24`，`attention_head_dim=128`
（注意力维度 3072），`joint_attention_dim=3584`（= Qwen2.5-VL 的 hidden size，文本流进来的维度）。

### 2.4 双流（MMDiT）结构——从 LoRA 目标层反推

本项目 LoRA 插在这 12 个模块上，它们精确地暴露了架构：

| 模块 | 属于 | 作用 |
|---|---|---|
| `to_q, to_k, to_v, to_out.0` | **图像流** | 图像 token 的 QKV 与输出投影 |
| `add_q_proj, add_k_proj, add_v_proj, to_add_out` | **文本流** | 文本 token 的 QKV 与输出投影 |
| `img_mlp.net.2` / `txt_mlp.net.2` | 两条流各自的 FFN | |
| `img_mod.1` / `txt_mod.1` | 两条流各自的 **adaLN 调制** | 把时间步 $t$ 与全局条件注入 |

**要点**：`add_*` 前缀就是「第二条流」。图文两路**各有独立权重**，但在 attention 里
**共享一次 softmax**（joint attention）——这样文本可以直接"看到"图像 token，反之亦然，
比 UNet 时代的 cross-attention 交互更充分。

`img_mod` / `txt_mod` 是 adaLN-Zero 式调制：把 $t$ 的 embedding 映射成 scale/shift/gate，
逐层调制特征。这是 DiT 注入时间步的标准做法。

### 2.5 【配置】3D RoPE

`axes_dims_rope=[16,56,56]` — 三个轴的旋转位置编码维度，分别对应
**(帧/图序号, 高, 宽)**。总和 $16+56+56=128$ = `attention_head_dim`。

第一个轴的存在很关键：**它让模型能区分"这是第几张输入图"**。多图条件编辑就靠它区分
源帧和各张商品参考图。这也解释了本项目那个核心发现——训练时只见过 2 张图（轴 0 只用到 0/1），
推理给 4 张图（轴 0 用到 0–3），是真正的分布外输入。

### 2.6 【配置】VAE 细节

```
z_dim: 16                              # latent 通道数
dim_mult: [1, 2, 4, 4]                 # → 空间 8× 下采样
temperal_downsample: [False, True, True]   # ← 时间维下采样：这是个视频 VAE
latents_mean / latents_std             # 逐通道归一化统计量
```

**为什么 16 通道，不是 SD1.5 的 4 通道**：latent 通道数决定重建上限。
4 通道压缩比高但细节损失明显（小字、纹理、人脸易糊）；16 通道重建保真度显著更好，
代价是 DiT 的 token 维度更大。SD3/FLUX/Qwen-Image 都转向了 16 通道。
**对本任务尤其重要**——服装纹理和 Logo 细节全靠它。

**`latents_mean` / `latents_std` 是什么**：VAE 编码出的 latent 各通道量纲不一致，
要先逐通道标准化到大致零均值单位方差，扩散过程才好训。
**这一步搞错（用错统计量、或忘了反归一化）会直接产出噪声图或灰图**，是常见 bug。

**注意它是视频 VAE**：`temperal_downsample` 的存在说明这是 Wan 系视频 VAE。
处理单图时按 T=1 使用。这也解释了 3D RoPE 第一个轴的由来——
它本来是时间轴，在编辑模型里被复用为"第几张输入图"。

**KL 而非 VQ**：连续 latent（KL 正则的 VAE），不是离散码本（VQ）。
扩散在连续空间上做，不需要码本。

### 2.7 为什么用 Qwen2.5-VL 当 text encoder，而不是 CLIP/T5

| encoder | 特点 | 局限 |
|---|---|---|
| CLIP text | 与图像对齐好 | **77 token 上限**，长指令直接截断 |
| T5-XXL | 长文本、语言理解强 | 纯文本，看不见图 |
| **Qwen2.5-VL** | LLM 级语言理解 + **原生看图** | 参数大（8.29B），显存贵 |

对本任务这是决定性的：

1. **指令长达 1592 字符**，CLIP 的 77 token 根本装不下
2. 指令里有大量**指代关系**——"图1 是源帧，图2 是商品，把图1 中人物的上衣换成图2 的款式"。
   这要求 encoder **同时理解文本和看到那几张图**才能把"图2"绑定到正确的视觉内容。
   T5 做不到，CLIP 做不到，**必须是 VLM**。
3. 需要理解否定与约束（"不要改变背景、姿势、面部"）——这是 LLM 级的语言能力，
   CLIP 的 bag-of-words 式表示对否定几乎无效。

**【配置】** `joint_attention_dim=3584` 正是 Qwen2.5-VL 的 hidden size，
文本表示直接进 DiT 的 joint attention。

## 3. 图像编辑：条件是怎么进模型的

### 3.1 数据字段与流向

```python
{
  "image":      "idm_synth/xxx.jpg",          # 目标图（GT），用于算损失
  "edit_image": ["viton_hd/person.jpg",       # 条件图 1：源帧
                 "viton_hd/cloth.jpg"],       # 条件图 2：商品参考
  "prompt":     "【输入图片】图1：源视频真实帧…"  # 1592 字符全文指令
}
```

训练一步：

1. VAE 编码**目标图** → 目标 latent $x_0$
2. VAE 编码**各条件图** → 条件 latent，拼进 token 序列
3. Text Encoder 编码 prompt（Qwen2.5-VL 还会看条件图）→ 文本 token
4. 采样 $t$，构造 $x_t$
5. DiT 在「$x_t$ + 条件 latent + 文本 token」上预测速度
6. 与真实速度回归，反传更新 DiT

**注意**：条件图是**拼接**进序列的（in-context conditioning），不是 cross-attention 的
独立分支。所以图的数量直接改变序列长度和位置编码占用——这正是多参考图失效的机制来源。

### 3.2 【实验】`zero_cond_t` 是什么

**【配置】** `transformer/config.json` 里 `zero_cond_t: true`。

含义：**条件图的 token 在时间步上被置零**——它们是干净的参考，不参与加噪轨迹，
所以不该被当作"第 t 步的噪声图"处理。Edit-2511 强制要求这个开关，训练时不加
`--zero_cond_t` 会训崩（条件图被误当噪声图处理）。

这是个很好的面试点：说明你读过配置、知道版本差异，而不是照抄命令。

### 3.3 训练侧不用 CFG

训练时 `true_cfg_scale`/`guidance_scale` 通常为 1，**classifier-free guidance 是推理技巧**：
推理时同时跑一次有条件、一次无条件，按 $\text{uncond} + s(\text{cond}-\text{uncond})$ 外推。
本项目推理用 `true_cfg_scale=4.0`。

**【配置】** `guidance_embeds: false` — 这个底座不是 guidance-distilled 模型
（所以日志里会出现 "guidance_scale is passed as 1.0, but ignored"）。

**CFG 的代价**：推理时每步要跑**两次**前向（有条件 + 无条件），
所以开 CFG 直接让推理耗时翻倍。这也是 guidance distillation（把 CFG 蒸进单次前向）
存在的意义。

### 3.4 动态分辨率与面积上限

不同素材长宽比各异，不能硬缩到正方形（人物会变形）。做法是**限制总像素数（面积），
让长宽比自由**：

$$s = \sqrt{\frac{P_{\max}}{W \times H}}, \quad (W', H') = (\text{round}_{k}(sW),\ \text{round}_{k}(sH))$$

- $P_{\max}$ 是面积上限（本项目约 1MP）
- 结果要**对齐到 patch 的整数倍**（VAE 8× × patch 2 = **16 的倍数**），否则无法 patchify

**为什么必须有上限**：token 数 $\propto$ 面积，而 attention 是 $O(N^2)$。
面积翻倍 → token 翻倍 → attention 计算量 4×、激活显存也随之涨。
**分辨率是显存与耗时的主控旋钮**（对应 `MAX_PIXELS`）。

**【实验】** 评测固定 768×1024（= 0.79MP，VITON 原生比例，在 1MP 训练上限内），
保证训练与评测分辨率同分布。

**连带影响（容易忽略）**：第 1.4 节说过 scheduler 开了 `use_dynamic_shifting`，
噪声 schedule 随 token 数变化。所以**改分辨率同时改了噪声分布**——
训练和推理分辨率不一致时，退化可能来自 schedule 偏移而非模型能力。

### 3.5 长指令（1592 字符）里装了什么

结构大致是：

```
【输入图片】图1：源视频真实帧 / 图2：商品图        ← 显式声明每张图的角色
【任务】把图1 中人物所穿上衣替换为图2 的款式       ← 主任务
【必须保持】背景、姿势、机位、面部身份、光照        ← locality 约束（最关键）
【不要处理】字幕/水印                            ← teacher 约定对齐（见 8.3）
【输出要求】分辨率、构图                          ← 格式约束
```

**为什么要这么长**：locality 在指令式模型里**没有架构保证**（对比 IDM-VTON 的 mask，
见 4.2），只能靠自然语言反复约束。「必须保持」那一段就是在用文本补回 mask 的作用。

**为什么训练必须用同样的长指令**：推理时用长指令，训练时用短指令，
模型就没学过"这么长的约束该怎么执行"。**指令分布必须对齐**——
这是本项目 v2 数据重做的原因。

**【实验】** 早期担心 1024 token 截断，实测 EditPlus pipeline 的 processor
**不截断也不切片**，约 2000 字符可全文进入模型。所以质量问题的主因是
**短训长推的域差**，不是截断。

## 4. 蒸馏：这里到底"蒸馏"了什么

### 4.1 三种蒸馏，别混

| 类型 | 传递什么 | 典型做法 |
|---|---|---|
| **知识蒸馏**（Hinton） | teacher 的 **soft logits / 中间特征** | KL 损失对齐输出分布 |
| **数据蒸馏 / 伪标注** | teacher 的**输出样本** | 用 teacher 造 (输入,目标) 对，学生做普通监督学习 |
| 步数蒸馏 | 多步采样 → 少步 | LCM、Turbo、DMD |

**本项目是第二种**：不接触 IDM-VTON 的 logits 或特征，只用它的**输出图**当 GT。
学生跑标准的扩散回归损失。

面试若被问「你做的是知识蒸馏吗」，准确回答：**是数据层面的蒸馏（伪标注式），
不是 logits 层面的知识蒸馏**——因为两个模型架构、输出空间、损失形式完全不同，
根本无法对齐 logits。

### 4.2 为什么要蒸馏，而不直接用专家模型

| | 专用 try-on（IDM-VTON） | 指令式编辑（Qwen-Image-Edit） |
|---|---|---|
| 输入 | 固定槽位：人物图 + 平铺衣 + **agnostic mask + densepose + 骨骼点** | RGB 图（数量可变）+ 自由文本 |
| 任务 | **只有一件** | 文本说什么做什么 |
| 「只改衣服」怎么保证 | **mask 几何约束**，架构层锁死 | 自然语言软约束，靠训练学到 |
| 部署 | 5 个模型级联 | 一次前向 |
| 失效模式 | 服装区域画不好（mask 保护其余区域） | **可能重绘整幕** |

**最深的一层洞察**：IDM-VTON 的 mask 既是枷锁也是保险。它让模型无法接受文本指令，
但也让它**不可能**破坏非服装区域。指令式模型拿到了灵活性，代价是**失去结构性保证**——
「只允许替换目标服装」只是一句建议，模型可以误读。

所以这次蒸馏本质是**用安全性换灵活性**，必须靠数据分布覆盖去补回那份保证。
这也是「多参考条件建模」被列为 P0 的根本原因。

### 4.3 unpaired 是关键

VITON 数据里同 id 的 (person, cloth) 是「这个人本来穿的那件衣服」。
如果拿它当训练对，目标图就是原图，模型学到的是**重建**而不是**换装**。

所以要用 **unpaired**：人 A 穿衣 B。IDM-VTON 生成「A 穿 B」的目标图，
这才构成真正的编辑对。

**【实验】** 配对生成时用断言强制：`person.stem != cloth.stem`（无自配）+ 跨批次无重复。

### 4.4 teacher 的天花板

学生最多学到 teacher 的水平，**teacher 的瑕疵会被当成正确答案学进去**。
所以评测里的 `MAD vs teacher` 衡量的是「像不像 teacher」，不是「像不像理想答案」。

主动说出这个边界是加分项。

## 5. 后训练：全参 SFT vs LoRA

### 5.1 LoRA 数学

对选定的线性层 $W \in \mathbb{R}^{d\times k}$，冻结它，另学两个低秩矩阵：

$$W' = W + \frac{\alpha}{r} BA, \quad B \in \mathbb{R}^{d\times r},\ A \in \mathbb{R}^{r\times k}$$

- $r$ 是 rank（本项目 16），$r \ll \min(d,k)$
- 可训参数从 $dk$ 降到 $r(d+k)$
- **【实验】** 本配置 LoRA ≈ 0.118B，相对 DiT 全参 20.43B 是 **1/173**
- 推理时可以 fuse：$W \leftarrow W + BA$，之后与底座加载方式完全一致，**零额外推理开销**

### 5.2 为什么 LoRA 要用更大的学习率

本项目 LoRA 用 1e-4，全参用 1e-5，差 10×。**这不是随手调的**：

- 全参直接改 $W$ 本身，$W$ 已经是预训练好的，大步长会破坏已有能力
- LoRA 改的是**增量** $BA$，且 $B$ 通常零初始化（保证训练开始时 $W'=W$）。
  增量要从 0 长到有效幅度，需要更大步长

**推论**：**loss 下降速度不能跨方法比较绝对值**——两者的有效步长差一个数量级。

### 5.3 什么时候该用哪个

| | LoRA | 全参 |
|---|---|---|
| 可训参数 | 0.118B | 20.43B |
| 优化器状态 | ~1.6GB/卡 | ~30.7GB/卡（已分片） |
| 分布式 | DDP 够 | **必须 ZeRO-3** |
| 训练时长（本项目） | 1h49m | 2h22m |
| 产物 | 226MB 适配器 | 40.86GB 全量权重 |

**【实验】200 样本结论**：全参在结构相似度（MAD vs teacher）上**显著更优**
（Δ=+0.34, t=+3.45），但 LoRA 在色彩分布上**显著更优**（t=+2.78）；
且 base 38.95 → 全参 8.76（提升 30.19），LoRA 到 9.10（提升 29.85），
**LoRA 拿到全参 98.9% 的收益**。

结论：统计上可区分，**工程上不足以否定 LoRA 选型**。这是「统计显著 ≠ 实际重要」的教科书例子。

### 5.4 【实验】小样本的陷阱

同一组对照，6 样本时 Δ=−0.09、t=−0.48（判"无差异"）；200 样本时 Δ=+0.34、t=+3.45
（判"显著，全参更优"）——**方向反转**。

**小样本给出的不是"差异不存在"，只是"分辨不出"。** 当时分辨力约 0.5 MAD，
真实差距 0.34，正好落在盲区。这两件事被混为一谈是最常见的实验解读错误。

附带：base 在 6 样本上 MAD 28.95、200 样本上 38.95——那 6 条对未训练模型偏易，
把"训练收益"低估了三分之一。**所有跨样本量的数字都必须标注 n**。

## 6. 多卡并行

### 6.1 DDP

每张卡放**一份完整模型**，各吃不同 micro-batch，backward 后梯度 all-reduce 求平均。

- 提高吞吐（有效 batch = 单卡 batch × 卡数）
- **完全不省参数显存**——每卡都是全量

### 6.2 ZeRO 三级

DeepSpeed ZeRO 把训练状态沿卡切分。设 $N$ 为卡数：

| Stage | 切分对象 | 单卡显存 |
|---|---|---|
| ZeRO-1 | 优化器状态 | 权重 + 梯度 + O/N |
| ZeRO-2 | + 梯度 | 权重 + G/N + O/N |
| **ZeRO-3** | + 参数 | **(P+G+O)/N** |

ZeRO-3 的代价：前向/反向时需要**按层 all-gather** 参数，用完立即释放 → 通信量增加。

### 6.3 为什么全参必须 ZeRO-3（显存账）

只训 DiT（20.43B），用 DDP 时**单卡**要放：

```
权重 bf16（含冻结的 TE/VAE）      ≈  54 GiB
DiT 梯度 fp32   20.43B × 4        ≈  76 GiB
AdamW m + v     20.43B × 4 × 2    ≈ 152 GiB
────────────────────────────────────────────
静态合计                           ≈ 282 GiB   ← 单张 80GB 卡不可能
```

即使 4 卡 DDP 也只是 4 份 282GiB 的复制，一点不解决问题。

ZeRO-3 分到 8 卡：

```
参数分片   40.86 / 8 ≈  5.1 GiB
梯度分片   40.86 / 8 ≈  5.1 GiB
优化器分片 245   / 8 ≈ 30.7 GiB   ← 大头
激活（有 GC 压着）    ≈ 数十 GiB
────────────────────────────────
实测峰值            ≈ 74.8 GiB / 80GB
```

**【实验】** 8 卡显存差仅 685 MiB（0.9%），证明分片均匀。

### 6.4 【实验】数据量翻倍，显存不变

数据 11,415 → 22,829，显存峰值 74.8GB → 74.8GB（误差 <0.1%）。

原因：ZeRO-3 的占用由**参数量与 batch size**决定，与 epoch 内样本总数无关。
数据翻倍只让**步数**翻倍（1427 → 2854），单步的前向/反向逐字不变。

这是个很好的追问答案：「为了更大数据集要不要换更大显存」→ 不需要，要的是时间。

### 6.5 ZeRO 与 FSDP 的关系

PyTorch FSDP 与 ZeRO-3 思路一致（都是全分片数据并行）。ZeRO 是 DeepSpeed 的实现，
FSDP 是 PyTorch 原生。选择通常取决于框架生态——本项目用 DiffSynth，
它的 example 配置走 Accelerate + DeepSpeed，所以用 ZeRO-3。

### 6.6 其他并行维度（会被问到）

| 并行 | 切什么 | 何时需要 |
|---|---|---|
| 数据并行 / ZeRO | 数据 + 训练状态 | 默认起点 |
| 张量并行（TP） | 单层权重矩阵 | 单层都放不下时 |
| 流水并行（PP） | 按层分段 | 层数极多、跨节点 |
| 序列并行 / Context | 序列维 | 超长上下文 |

本项目 20.43B + 80GB 卡，ZeRO-3 已足够，不需要 TP/PP——**能用最简的并行就别叠复杂度**。

## 7. 训练工程细节

### 7.1 bf16 vs fp16

| | fp16 | bf16 |
|---|---|---|
| 指数位 | 5 | **8**（与 fp32 相同） |
| 尾数位 | 10 | 7 |
| 动态范围 | 窄，易上下溢 | **宽** |
| 需要 loss scaling | 是 | **否** |

bf16 牺牲精度换动态范围，训练稳定性明显更好，是当前大模型训练默认选择。
A100/H100 都有原生支持。

### 7.2 Gradient Checkpointing

前向时**不保存**中间激活，反向时**重算**。

- 省激活显存（可达数倍）
- 多一次前向的计算开销（约 +30% 时间）
- 与 ZeRO-3 叠加时，重算可能触发再次 all-gather 参数 → 通信增加，但通常仍优于存满激活
- 注意：重算必须与首次前向同输入同权重，**有 Dropout 时要复用 RNG 状态**

**【实验】** 日志里反复出现 `Do not find activation_checkpointing config in deepspeed config, skip`
是良性的——本项目用的是模型层的 GC（`--use_gradient_checkpointing`），
不是 DeepSpeed 自己的 activation checkpointing wrapper，两套机制独立。

### 7.3 【实验】CPU Offload：两套机制，别混

项目里"offload"出现在两个完全不同的位置，面试被问到时必须先区分。

#### (a) 训练侧：ZeRO-Offload —— 备好了但没启用

**【配置】** `configs/accelerate_zero3.yaml`（实际使用）：

```yaml
zero_stage: 3
offload_optimizer_device: none     # ← 没开
offload_param_device: none         # ← 没开
zero3_init_flag: true
zero3_save_16bit_model: true
num_processes: 8
mixed_precision: bf16
```

**【配置】** `configs/accelerate_zero2_offload.yaml`（fallback，`DS_PROFILE=zero2_offload`）：

```yaml
zero_stage: 2
offload_optimizer_device: 'cpu'    # ← 优化器状态搬到 CPU
offload_param_device: 'cpu'
num_processes: 4
```

**【实验】三次训练跑的都是 zero3 无 offload**（三份 run report 里都记为「无 param/optimizer offload」）。

**为什么不开**：8 卡分片后实测峰值 74.8/80GB，够用。ZeRO-Offload 把优化器状态搬到 CPU 后，
每步都要走 PCIe 来回搬运 + 在 CPU 上执行 Adam 更新，通常慢 2–4 倍。
**显存够就别开——它是救命手段，不是优化手段。**

fallback 存在的意义是卡不够时（4 卡）还能跑：优化器状态 245GiB 是最大头，
搬到 CPU 后 GPU 侧压力骤降。

> 一处配置冗余：`zero_stage: 2` 时 DeepSpeed 只认 `offload_optimizer`，
> **`offload_param` 在 ZeRO-2 下不生效**（ZeRO-2 本身不分片参数）。那行是无害的多余项。

#### (b) 【配置】两个容易被忽略的 ZeRO-3 flag

| flag | 作用 |
|---|---|
| `zero3_init_flag: true` | **模型初始化时就分片**。否则每张卡要先完整实例化 20.43B 模型再切分，光 init 就 OOM |
| `zero3_save_16bit_model: true` | 存 ckpt 时把分片参数 **all-gather 回完整 bf16 权重** |

第二个 flag 直接决定了下游：正因为它，才能拿到那个 1933 tensor 的完整 DiT 权重文件，
第 7.4 节的权重嫁接才有可能。**若关掉，存出的是一堆分片，得先跑
`zero_to_fp32.py` 才能用。**

#### (c) 推理/评测侧：diffusers model CPU offload —— 实际大量使用

**【实验】** `zero_shot_compare.py` 里 `pipe.enable_model_cpu_offload()`，
评测脚本通过 `--cpu-offload` / `CPU_OFFLOAD=1` 开启，**这个是常态开着的**。

**为什么必须开**：模型三件套 bf16 合计 57.7GB。评测跑在**共享卡**上，
常拿不到一整张空的 80GB，别的租户占掉一部分就 OOM。

**为什么它对扩散 pipeline 特别划算**：pipeline 的阶段是**严格顺序**的——

```
Text Encoder 编码 → 编完就不再需要
      ↓
DiT 迭代去噪（占大部分时间）
      ↓
VAE 解码 → 只在最后一步用
```

三个组件**从不需要同时在显存里**。所以按模块搬进搬出，峰值从 57.7GB
降到约等于最大单个组件（DiT 40.86GB），而搬运只发生在阶段切换时，
**不在去噪循环内部**——开销几乎可忽略。这和训练侧 offload 每步都搬完全不同。

#### (d) offload 的三种粒度

| 方式 | 粒度 | 代价 |
|---|---|---|
| `enable_model_cpu_offload()` | 组件级（TE / DiT / VAE） | 很小（本项目用这个） |
| `enable_sequential_cpu_offload()` | 子模块级，逐层搬 | 省得多，但**慢数倍** |
| ZeRO-Offload（训练） | 优化器状态 / 参数 | 每步搬运，慢 2–4× |

追问「还能更省吗」→ 换 sequential 能再降一档，代价是速度；
再往下就是降分辨率（`MAX_PIXELS`）或减采样步数。

### 7.4 【实验】权重嫁接（DiT-only ckpt → 完整模型目录）

全参训练只训 DiT，DiffSynth 存出的 `epoch-0.safetensors` **只含 DiT 的 1933 个 tensor**，
key 是裸模块名。它**不能当模型目录加载**，因为缺 text_encoder / VAE / tokenizer / processor /
各种 config，而且 diffusers 要求 transformer 子目录按 `transformer.*` 前缀分片序列化。

`apply_full_dit_ckpt.py` 做的事：

1. `copytree(base → out)` 拿到所有冻结组件
2. 组装完整 pipeline
3. 加载 DiT ckpt，**key 前缀归一化**（去掉 `pipe.dit.` / `transformer.`）
4. `load_state_dict(strict=False)` 灌进 transformer，打印 missing/unexpected 做校验
5. `save_pretrained` 按 diffusers 标准重新序列化

**【实验】** 校验通过标准：`missing=0 unexpected=0`，1933 tensors 全加载，
且 `img_in.bias` 的 sum 从 219.20（base）变成 219.08（fused）——**确认权重真的换了**。
这一步很容易"看起来成功但其实没生效"，必须验数值。

### 7.5 【实验】同优化步数为什么重要

$$\text{优化步数} = \left\lceil \frac{\text{样本数}}{\text{单卡 batch} \times \text{卡数} \times \text{grad\_accum}} \right\rceil \times \text{epochs}$$

最初那版 LoRA 用 4 卡 → 有效 batch 4 → 11,415 条跑出 **2854 步**；
全参用 8 卡 → 有效 batch 8 → **1427 步**。

同样的数据，LoRA 多做了一倍的梯度更新。这时即使评测有差异，也说不清是
「LoRA vs 全参」还是「更新次数多一倍」造成的——**多了一个自变量**。

所以对照那版 LoRA 固定用 8 卡，步数同为 1427。脚本启动前打印
`expected_steps=1427` 做自检。

**常见陷阱**：只记得"用同一份数据"，但换卡数、改 grad_accum、或数据量变了却沿用原步数，
都会悄悄引入第二个变量。

### 7.6 【实验】LR 调度器

DiffSynth 用的是 `ConstantLR`（`runner.py`），默认 `factor≈1/3`、`total_iters=5` ——
即前 5 步半速热身，之后恒定。**不是 cosine/linear decay，也不绑 epoch 数**。

这个细节影响"续训"的设计：没有 schedule 状态要接续，但优化器动量会从零重启。

### 7.7 DiffSynth-Studio 是什么

**开源 diffusion 训练/推理框架**（ModelScope 出品）。提供统一 pipeline 抽象、
多模型支持、LoRA 与全参训练循环，以及 Accelerate + DeepSpeed 集成。
本项目 editable 安装，训练循环在 `diffsynth/diffusion/runner.py`。

**为什么用它而不是自己写训练循环**：Qwen-Image-Edit 这类多图条件编辑模型，
「条件图怎么进序列、`zero_cond_t` 怎么处理、多图 RoPE 怎么排」都有大量实现细节，
自己写极易在静默处出错（训得动但学错东西）。用官方 example 支持的框架，
把精力放在数据与实验设计上。

**必须诚实的口径**：**框架是它的，我做的是数据链路、对照实验设计与评测协议。**
我读它的源码到能指出 `runner.py:66` 把 scheduler 写死成 `ConstantLR`（见 7.6），
但没有改它的训练循环。

### 7.8 【实验】训练配置全表

两次训练除下半部分标注的差异外全部对齐。

| 项 | 全参 SFT | LoRA v2（对照） |
|---|---|---|
| 底座 / 初始化 | `Qwen-Image-Edit-2511` base | 同（同一 base，非续训） |
| 可训练 | **仅 DiT 20.43B**（1933 tensor） | **DiT LoRA r16 ≈ 0.118B**（12 个模块） |
| TE / VAE | 冻结（8.29B / 0.13B） | 冻结 |
| **数据** | `converted_idm_synth_train_v2`，**11 415 条** | **同一批文件、同 11 415 条** |
| epoch / dataset_repeat | 1 / 1 | 1 / 1 |
| **优化步数** | **1 427** | **1 427**（刻意对齐，见 7.5） |
| 卡数 / 有效 batch | 8 / 8 | 8 / 8 |
| grad_accum | 1 | 1 |
| max_pixels | 1 048 576（≈1MP） | 同 |
| 精度 | bf16 mixed | 同 |
| Gradient Checkpointing | 开 | 开 |
| `zero_cond_t` | 开（强制） | 开 |
| `find_unused_parameters` | True | True |
| 优化器 | AdamW，wd 0.01 | AdamW，wd 0.01 |
| LR scheduler | ConstantLR | ConstantLR |
| — 以下是方法本身决定的差异 — | | |
| **学习率** | **1e-5** | **1e-4**（10×，见 5.2） |
| **分布式** | **DeepSpeed ZeRO-3** | **DDP**（Accelerate `--multi_gpu`） |
| 优化器状态 | ~30.7 GB/卡（已分片） | ~1.6 GB/卡 |

**软件版本**（复现要问的）：torch 2.6.0+cu124 / deepspeed 0.19.5 /
accelerate 1.14.0 / diffusers 0.39.0。

**硬件**：8× NVIDIA H100 80GB **HBM3**，NVLink P2P on。
NVLink 对 ZeRO-3 很关键——逐层 all-gather 的通信量大，走 PCIe 会明显掉速。

**关于 AdamW**：用 AdamW 而非 Adam，因为它把 weight decay 从梯度里**解耦**出来
（Adam 的 L2 正则会被自适应学习率缩放，等效强度失控）。
显存账里那个「×8」= m 和 v 各 4 字节（fp32）。

**为什么步数是 1427 而不是 1426**：$11415/8 = 1426.875$，分布式 sampler
**不 drop_last、向上 pad 到卡数的整数倍** → 总样本变 11 416（多 1 条重复），
每 rank 1427 步。b1+b2 同理：22 829 → pad 到 22 832 → 2854 步。
这是个很好的细节题——能答出来说明你真的核对过步数而不是照抄日志。

### 7.9 【实验】显存实测：一个反直觉的结果

| | LoRA DDP | 全参 ZeRO-3 |
|---|---|---|
| 稳态/卡 | **~68.4 GiB（85%）** | ~74.4 GiB |
| **峰值/卡** | ~68.9 GiB | **74.8 GiB（91.7%）** |
| 余量/卡 | ~12 GiB | ~5.2 GiB |
| 8 卡最大差 | 588 MiB | 685 MiB（0.9%，分片均匀） |
| 稳态 stdev | — | **234 MiB**（极平稳，非泄漏增长） |
| 爬坡到稳态 | — | ~2 分钟（7 MiB → 60.6 → 73.6 GB） |
| util 均值 | ~100% | 94.5%（步间掉 0% = 数据加载 + all-gather） |
| 功耗均值 | 526–682 W | **603 W**（H100 TDP 700W 的 86%），峰值 715W boost |
| 温度均值 | 57–74°C | 64°C，峰值 78°C（低于 80°C 降频线） |

**反直觉点**：全参 ZeRO-3 的峰值**比 LoRA DDP 还高 6.8 GiB**。
直觉以为"用 ZeRO-3 是为了省显存"，实际拆开看：

```
LoRA DDP（每卡）
  冻结底座 bf16（DiT 40.9 + TE 15.5 + VAE 0.3）  ≈ 56.7 GiB  ← 整模复制，大头
  LoRA 参数 + fp32 梯度 + AdamW（仅 118M）        ≈  1.6 GiB  ← 极小
  GC 后激活                                       ≈ ~10 GiB
                                                  ≈ 68 GiB

全参 ZeRO-3（每卡，三者都 /8）
  DiT 参数 bf16   40.9/8                          ≈  5.1 GiB
  DiT 梯度        40.9/8                          ≈  5.1 GiB
  fp32 master + AdamW m,v（3×20.43B×4B）/8        ≈ 30.7 GiB  ← 大头
  GC 后激活 + all-gather 瞬态                     ≈ ~34 GiB
                                                  ≈ 74.8 GiB
```

**正确的表述**：ZeRO-3 不是"更省"，而是**"让全参成为可能"**。
纯 DDP 跑全参每卡要 245 GiB 优化器状态 → 必 OOM；ZeRO-3 切到 30.7 GiB 才塞得进。
LoRA 能用 DDP，恰恰是因为它**不为 20B 付优化器**——所以"每卡复制整模 56.7 GiB"
反而比"分片优化器 30.7 + 参数 5.1 + 梯度 5.1 + 更大激活"更便宜。

**一句话**：两者不是"谁更省"，是**"能改多少参数"的能力差**。

**为什么 LoRA 余量 12GB 还不上 ZeRO-3**：可训只有 118M，DDP 的梯度 all-reduce
只传 ~0.47 GiB，通信极轻；换 ZeRO-3 会引入逐层 all-gather 的额外通信与重算，
**对 LoRA 是净负**。所以「LoRA 配 DDP、全参配 ZeRO-3」是各自最优，不是凑合。

### 7.10 【实验】时间与吞吐

| | 步数 | s/it | 纯训练 | 端到端 | 吞吐 |
|---|---|---|---|---|---|
| 全参 b1（11 415 条） | 1 427 | **5.87** | 2h20m | **2h22m** | 1.36 samples/s |
| 全参 b1+b2（22 829 条） | 2 854 | **5.87** | 4h39m | **4h41m** | 1.36 samples/s |
| LoRA v2（11 415 条） | 1 427 | **4.60** | 1h49m | ~1h51m（含 fuse 1m27s） | — |

**LoRA 比全参快 22.3%**，原因四条：① 无 ZeRO-3 逐层 all-gather；
② `optimizer.step` 只更新 118M（vs 20B）；③ 无 fp32 master 权重同步；
④ DDP 只 all-reduce 118M 梯度。反向仍要过冻结层（梯度得传到更早的 LoRA 层），
GC 重算两边都有，净结果 LoRA 仍快。

**数据翻倍 → 墙钟线性翻倍（2.00×）、单步速度不变（5.87 两边相同）、显存不变。**
三条一起构成 ZeRO-3 行为的完整刻画：单步成本由模型与 batch 决定，
数据量只改变步数。

**单卡吞吐 0.170 samples/s** —— 折算约 5.9 秒处理一个样本。
这个数字看着低，但注意每个样本要过 8.29B 的 VL encoder + 20.43B DiT 的完整前反向，
且分辨率接近 1MP。

### 7.11 【实验】产物形态与体积

| 产物 | 体积 | 能否直接推理 |
|---|---|---|
| 全参 DiT ckpt（`epoch-0.safetensors`） | **40.86 GB**，1933 tensor | ❌ DiT-only，裸 key，缺 TE/VAE/config |
| 全参 fused 完整目录 | ~54 GB | ✅ |
| LoRA adapter | **226 MB** | ❌ 需底座 |
| LoRA fused 完整目录 | **54 GB** | ✅ |

**两种"合并"的机制不同**（容易被问）：

- LoRA 是**加法**：$W' = W + \frac{\alpha}{r}BA$
- 全参是**替换**：$W \leftarrow W_{\text{sft}}$

**产物体积差 180×**（226MB vs 40.86GB）是 LoRA 在工程上的最大优势——
多任务时可以只存多份适配器共享一个底座。

### 7.12 跑 2 个 epoch 会更好吗（高频追问）

分三层答：

1. **调度层无障碍**：`ConstantLR` 不绑定 `num_epochs`（7.6），2 epoch 就是
   平坦 LR 再延伸 1427 步，没有"schedule 为 1 epoch 设计"的副作用。
2. **loss 层边际收益小**：全参末 4 个窗口 0.0318 → 0.0314 → … → 0.0311 已基本平了，
   而单步噪声远大于这个趋势。
3. **风险层反而更可能有害**：参数/数据比是 **20.43B / 11 415 ≈ 1.8M 参数每样本**，
   极端悬殊。第二遍把同一批**唯一**图再喂一次，显著抬高记忆化风险，
   而当前没有 val loss，单看 train loss 判不出过拟合膝点。

**结论**：瓶颈是数据的量与多样性，不是 epoch 数。加新 pair 比加 epoch 值得——
但要加**实体多样性**，不是配对排列（见 8.2 的阴性结果）。

## 8. 数据工程

### 8.1 为什么要跨批次去重

VITON 自带的 `train_pairs.txt` 只给了**一种**固定配对，第一批就用完了。
扩量要生成新的配对排列，此时必须保证：

1. **无自配**：`person.stem != cloth.stem`（否则退化成重建任务）
2. **跨批次无重复**：同一 (人物, 服装) 组合出现两次会促成记忆化而非泛化
3. **批内无重复**

**【实验】** 三项都在写盘前用断言强校验，不通过直接崩——**脏数据进训练集比不训更糟**。

### 8.2 【实验】组合数上限 vs 多样性上限

VITON train：11,647 人物 × 11,646 服装 ≈ **1.36 亿**组合，看似无限。

**但视觉素材上限只有 11,647 张人物图 + 11,647 件服装。** 扩 k 轮只是重新排列，
不新增任何人物或服装本体，收益递减。

**【实验】证据**：配对数量翻倍（11,415 → 22,829，多耗 2.3h 算力），
三项指标全部无显著变化。**信息量来自分布覆盖，不是条数。**

### 8.3 混合多个 teacher 的约定冲突

若引入 GPT 的真实帧输出作第二 teacher，会出现：IDM 样本**没有字幕**、
GPT 样本**会重绘字幕**。同一条指令模板下给出矛盾目标，模型学成随机二选一。

解法：**在指令里显式声明**（"不处理字幕" vs "将字幕改写为 X"），
让指令与目标严格一致。这顺带解决了 prompt 单一的问题。

### 8.4 数据许可（会被问，别答错）

| 来源 | 许可 |
|---|---|
| VITON-HD | **CC BY-NC** |
| IDM-VTON | **CC BY-NC-SA** |

**NC = 非商用**。派生数据（本项目合成的 25K 监督对）继承这一限制，
**SA 还要求衍生作品同样开放**。

主动说清这一点是加分项：它说明你知道"模型能跑"和"模型能上线"是两回事。

## 9. 评测指标

### 9.1 MAD（Mean Absolute Difference）详解

**【实验】实现**（`zero_shot_compare.py: mad_and_hist`）：

$$\text{MAD}(a,b) = \frac{1}{HW}\sum_{i}\big|\,L(a_i)-L(b_i)\,\big|, \qquad L = 0.299R+0.587G+0.114B$$

- 先把 b 用 **LANCZOS** resize 到 a 的尺寸（否则尺寸不同无法逐像素比）
- PIL `.convert("L")` 用的是 ITU-R 601-2 luma 系数（上式）
- float32 计算，**尺度 0–255**

**怎么读这个数**：MAD = 8.76 意味着平均每个像素的灰阶差 8.76/255 ≈ **3.4%** 的满量程。
MAD = 0 是逐像素相同；两张无关照片通常在 40–80。

**为什么用 L1 而不是 MSE/L2**：
1. L1 保持**原始单位**（灰阶），可以直接说"平均差 8.76 灰阶"；MSE 是平方单位，不可解释
2. L2 会被少数大偏差主导——服装区域本来就该大改，MSE 会让这一小块吃掉整个指标
3. L1 对"大面积轻微改动"和"小面积剧烈改动"的相对惩罚更均衡，正好是我要区分的两种失效

**为什么转灰度而不是在 RGB 上算**：为了**把结构和颜色拆成两个正交指标**。
灰度 MAD 只管"哪些像素动了、动了多少"（空间/结构），颜色交给直方图。
如果在 RGB 上算 MAD，一个数里混着结构与色彩两种变化，出问题时无法归因。

**两个盲点（要主动说）**：
- **同明度换色几乎测不到**：深蓝 → 同明度深红，luma 几乎不变 → 这正是配 hist corr 的原因
- **全局亮度偏移会虚高**：整图 +10 亮度、结构完全没动，MAD 也会是 10

### 9.2 hist corr（H-S 二维直方图相关）详解

**【实验】实现**：

```python
ha = cv2.cvtColor(rgb_a, cv2.COLOR_RGB2HSV)
hist = cv2.calcHist([ha], [0, 1], None, [32, 32], [0, 180, 0, 256])  # H,S 通道
cv2.normalize(hist, hist)                                            # 默认 L2 归一化
corr = cv2.compareHist(hist_a, hist_b, cv2.HISTCMP_CORREL)           # 皮尔逊相关
```

$$d(H_1,H_2)=\frac{\sum_i (H_1(i)-\bar{H_1})(H_2(i)-\bar{H_2})}{\sqrt{\sum_i (H_1(i)-\bar{H_1})^2 \sum_i (H_2(i)-\bar{H_2})^2}}$$

范围 −1~1，**越接近 1 越像**（注意方向与 MAD 相反，MAD 是越低越好）。

**三个设计选择**：

| 选择 | 原因 |
|---|---|
| 只取 **H、S**，丢掉 V | V（明度）已经被 MAD 覆盖了，带上就是重复测量，两个指标会同向共动，失去互补性 |
| **32×32** = 1024 bin | 太细 → 直方图稀疏、被噪声支配；太粗 → 邻近色分不开。32 是常用折中 |
| **L2 归一化** | 把直方图变成单位向量，消掉图像分辨率/像素总数的影响，不同尺寸可比 |

> OpenCV 的 H 通道范围是 **0–179**（把 0–360° 折半塞进 uint8），所以 range 写 `[0,180]`。
> 这是个常见踩坑点。

**盲点**：**完全没有空间信息**。把衣服的颜色整块搬到背景上，H-S 直方图可以一模一样。
所以它必须和 MAD 一起看，单独用会被骗。

### 9.3 为什么不用 PSNR / SSIM / LPIPS / FID / CLIP

先明确要测什么：**不是"生成质量好不好"，而是"改动是否局部且正确"**。
这决定了指标取舍。

| 指标 | 为什么不用 |
|---|---|
| **PSNR** | 就是 MSE 取对数，和 MAD 同属像素级但更被大偏差主导，且没有颜色/结构语义。相比 MAD 只多了不可解释性 |
| **SSIM** | 比 PSNR 好，测局部亮度/对比度/结构。但它会**惩罚该改的地方**——服装区域必须变，SSIM 一律记为"结构损失"，分数无法区分正确换装与破坏 |
| **LPIPS** | 引入另一个网络（VGG/AlexNet）的偏好，指标变化可能来自那个网络而非我的模型；还要额外 GPU 开销 |
| **FID** | **分布级指标，需要成千上万样本，且无法逐样本出分**。逐样本出分是配对检验的前提（第 10.1 节），用 FID 就做不了显著性检验 |
| **CLIP-score** | 测图文对齐。**整幕重绘也能拿高分**（画面确实符合"穿红色上衣"），对"只改该改的"完全不敏感——恰恰是我要测的失效模式 |
| **DINO 相似度** | 语义级相似，对局部像素改动同样钝 |
| **人工评测** | 最可靠，但慢、贵、不可复现，不适合做几十次对照迭代。适合最后验收 |

**MAD + hist corr 的取舍**：牺牲"感知相似度"的精确性，换来**逐样本可出分、可配对检验、
可直接可视化、零外部依赖、完全可解释**。对"改动量与改动位置"这个具体问题，够用且不引入混淆。

追问「那你怎么保证不是指标选得刚好好看」→ 答：配套差分可视化（第 9.6 节）做人眼交叉验证，
且两个指标测正交维度、方向相反，很难同时被同一种作弊模式骗过。

### 9.4 关键：用基线当刻度

有 GT 时有两列指标，回答两个不同问题：

| 列 | 问题 |
|---|---|
| MAD vs person | 模型**改了多少**（改动量） |
| MAD vs teacher | 模型**离目标多远**（正确性） |

单看任一列都会被骗。**`MAD(person, teacher)` 是刻度**（本项目 6 样本上是 18.64）：
它是"一次正确换装必然产生的改动量"，同时是第二列的**及格线**——
因为模型只要原样输出源图就能拿到这个分。**得分高于它，等于比交白卷还差。**

**【实验】** base 在 6 样本上改动量 35.65（≈刻度两倍，改太多）、距 teacher 28.95（>18.64，
比什么都不做还远）→ 在改错的东西。

### 9.5 没有 GT 时的陷阱

业务域没有 GT，只能测"改动量"。此时 **MAD 低不代表更好**。

**【实验】** full_sft 的 MAD（23.24）比 GPT（37.28）还低，但那是因为**该改的没改**：
产品是上下装套装，GPT 上下都换，它只换了上衣、留着原短裤。
**欠编辑会伪装成好成绩。**

### 9.6 标量看不出差异分布在哪

「重绘整幕」和「精确换装」可能给出相近的 MAD。所以配套：

- **差分热力图** $|x - \text{teacher}|$，固定裁剪在 128（**固定**才能跨面板、跨轮次比较）
- **H-S 直方图**，真实 H/S 坐标轴
- **per-pixel 差异 CDF**：横轴差异值、纵轴"差异小于该值的像素占比"。
  它能拆开被均值掩盖的两种情况——「少数像素差很多」vs「所有像素差一点」

**【实验】** 热力图里最有信息量的一格是 $|person-teacher|$——它画出"正确换装该动哪些像素"
（只有上衣区域发红）。拿模型的热力图与它对照，一眼区分局部编辑与整幕重绘：
base 连人脸都在发亮（身份被改），训练后的模型大面积深蓝。

### 9.7 【实验】「样本间波动收窄 4.9×」是什么意思

这是简历上那个数，必须能讲清。它**不是均值，是单样本 MAD 的标准差**
（n=200，`mad_vs_teacher` 在 200 个样本上的离散程度）：

| 模型 | MAD 均值 | **单样本 stdev** | 相对 base 收窄 |
|---|---|---|---|
| base | 38.95 | **20.56** | — |
| lora_v2_lr1e-4 | 9.10 | 4.09 | 5.02× |
| **full_sft_b1** | **8.76** | **4.24** | **4.85× ≈ 4.9×** |
| full_sft_b1b2 | 8.92 | 4.16 | 4.95× |

**为什么这个数比均值更重要**：base 的 stdev 20.56 意味着它**时好时坏**——
有的样本几乎不动（MAD 17），有的整幕重绘（MAD 40+）。均值只告诉你"平均多差"，
标准差告诉你**"能不能信它"**。

**放到业务里看**：这是**视频关键帧**管线。一条视频要处理多帧，
只要有一帧崩了，整条视频就废了。所以真正决定可用性的是**最坏情况和一致性**，
而不是平均分。一个"平均不错但十帧崩一帧"的模型在生产里是不可用的。

**所以训练的收益其实是两层**：均值从 38.95 降到 8.76（**准确性**），
同时波动收窄 4.9 倍（**可靠性**）。第二层往往被忽略，但对落地更关键。

**【实验】** n=6 时也观察到同一现象（base stdev 10.90 → full_sft 1.52），
但注意**两个样本量下的 stdev 不可直接比较**（n=6 的 stdev 本身估计极不稳），
引用时必须标注 n=200。

### 9.8 【实验】留出集构造与可复现性

**为什么没有数据泄漏**——隔离发生在 **split 级别**，不是随机切分：

| | 用的 split | 目录 |
|---|---|---|
| 训练 | VITON-HD **train** | `synth/idm_unpaired_train` |
| 评测 | VITON-HD **test** | `synth/idm_unpaired` |

两个 split 的**人物本体与服装本体都不重叠**，所以不存在"同一个人换个配对又出现在测试集"
这种泄漏。这比在同一批数据上随机切 train/test 更干净——后者人物会跨集重复出现。

**抽样可复现**：`random.Random(seed=0).shuffle(rows)` 后取前 n。固定 seed 保证
①换机器换时间结果一致；②**所有模型评的是同一批样本**——这是配对检验成立的前提。

**【实验】推理配置全部固定**，所有模型共享：

```
steps          = 40
true_cfg_scale = 4.0
size           = 768×1024   # VITON 原生比例，在 1MP 训练上限内
seed           = 0
prompt         = 同一 builder、同一参数重建（1592 字符）
```

prompt 用**训练时那个 builder 和那套参数**重建（`overlay=none`、1 张商品图），
保证评测与训练在同一 prompt 分布上——否则测出来的是域差而非模型差。

**这段的意义**：这样一来**唯一的自变量是模型权重**。面试官问"你怎么保证是公平对比"，
就答这一串固定项 + split 级隔离 + 同批样本。

## 10. 统计方法

### 10.1 为什么用配对检验而不是比均值

所有模型跑的是**同一批样本**，所以应按样本作差再看均值与标准误：

$$t = \frac{\bar{d}}{s_d/\sqrt{n}}, \quad d_i = m_i - r_i$$

配对消掉了「样本难度」这个最大的方差来源。实测差别巨大：
配对后 $s_d \approx 0.4$，而独立比较时各模型自身 sd 是 1.3–1.9。
n 小的时候，独立比较几乎必然得出"无差异"。

**记住临界值**：双侧 p<0.05 时，df=5（n=6）要 |t|>2.57；df=199（n=200）只需 |t|>1.97。

### 10.2 多重比较：一个必须主动承认的问题

**【实验】** LR 扫描做了 4 个配置 × 3 个指标 ≈ **12 次检验**。
每次 α=0.05，**期望假阳性 12×0.05 = 0.6 个**——也就是说"随便都能撞出一个显著"。

**Bonferroni 校正**：把阈值收紧到 $\alpha/m = 0.05/12 \approx 0.0042$，
df=199 时 t 临界值从 1.97 升到约 **2.88**。

拿它重新审视本项目的两个主结论：

| 结论 | t | 过 α=0.05？ | 过 Bonferroni？ |
|---|---|---|---|
| 全参 MAD 优于 LoRA | 3.45 | ✅ | ✅ 3.45 > 2.88 |
| LoRA 色彩优于全参 | 2.78 | ✅ | ❌ 2.78 < 2.88 |

**所以诚实的说法是**：全参在结构相似度上的优势经得起多重比较校正；
**LoRA 的色彩优势过不了**，只能算"提示性证据"，不能当结论用。

主动讲出这一点比藏起来强得多——面试官若自己算出来，性质就完全不同了。
（Bonferroni 偏保守，Holm-Bonferroni 或 Benjamini-Hochberg FDR 更有效力，
但在 12 次检验这个量级差别不大。）

### 10.3 【实验】t 检验的前提到底满不满足（实测，附稳健性验证）

配对 t 检验假设**差值 $d_i$ 近似正态**（注意：不要求原始指标正态）。
这个前提在 n=6 时无从检验，但 **n=200 的数据可以直接测**
（`scripts/check_paired_assumptions.py`）：

| 检验（$d_i$ = LoRA − full_sft，MAD vs teacher，n=200） | 结果 |
|---|---|
| 均值 / 中位数 | +0.339 / +0.280 |
| 标准差 | 1.388 |
| 极差 | **−11.35 ~ +6.03** |
| 偏度 skewness | **−2.70**（0 = 对称） |
| 超额峰度 excess kurtosis | **+26.99**（0 = 正态） |
| Shapiro-Wilk | W=0.686，**p = 4.4×10⁻¹⁹ → 强烈拒绝正态** |

**结论一：正态假设明确不成立。** 差值是**严重重尾**分布——大多数样本差异很小，
但存在少数两个模型表现悬殊的样本（最极端一条 LoRA 比全参好 11.35）。
这符合直觉：两个模型都会偶发大失败，而失败是稀疏事件。

**结论二：但主结论仍然成立，且比原先更稳。** 两个独立理由：

1. **n=200 时 CLT 保护的是均值的抽样分布**，不要求 $d_i$ 本身正态。
   t 检验对这种违反相当稳健。
2. **换成不假设任何分布的 Wilcoxon 符号秩检验做交叉验证**：

| 方法 | 统计量 | p | 判定 |
|---|---|---|---|
| 配对 t 检验 | t = +3.453 | 0.00068 | 显著 |
| **Wilcoxon 符号秩** | W = 4516.5 | **< 0.00001** | **显著，同向** |

两者一致，且 Wilcoxon 对离群点稳健却给出更强显著性 →
**结论不是被那个 −11.35 的离群样本驱动的**。

**结论三：n=6 的问题是功效，不是检验方法。**
那 6 条是这 200 条的前 6 个子集，可以直接回算：

| n=6 上 | 统计量 | p | 判定 |
|---|---|---|---|
| 配对 t 检验 | t = −0.483 | 0.650 | 无显著差异 |
| Wilcoxon | W = 8.0 | 0.688 | 无显著差异 |

**两种方法给出同样的"分辨不出"。** 所以"n=6 该换 Wilcoxon"作为补救是无效的——
换检验方法不会改变任何结论。n=6 的唯一问题是**功效不足**
（MDE 0.46 > 真实效应 0.34，见 10.5），与分布假设无关。

**结论四（最反直觉）：n=6 时连"检验假设"这件事本身都做不了。**
在那 6 条上跑 Shapiro-Wilk：W=0.925，**p=0.54 → 不拒绝正态**，
偏度 −0.25、峰度 −1.34，看起来完美正态。

但这个"通过"毫无意义——**正态性检验在 n=6 时同样没有功效**。
真实分布严重重尾（全量 p=4×10⁻¹⁹），6 个点根本测不出来。
所以小样本的困境是**递归**的：不仅测不出效应，连"能不能用这个检验"也测不出。

> **口径修正**：早期版本写过"n=6 时 t 检验不合法、该用 Wilcoxon"。
> 关于假设违反的直觉是对的（实测确认了严重非正态），
> 但把 Wilcoxon 当补救是错的——实测两种方法在 n=6 上结论完全相同（p=0.65 vs 0.69）。
>
> **准确说法**：正态假设确实被违反，但它没有改变任何结论——
> n=200 有 Wilcoxon 交叉验证兜底，n=6 换方法也一样测不出。
> **小样本失败的唯一原因是功效不足，与分布假设无关。**

### 10.4 效应量：显著 ≠ 重要

p 值只说"差异是否真实"，不说"差异有多大"。要看**效应量**。
配对设计用 Cohen's $d_z$，且有个便捷关系：

$$d_z = \frac{\bar{d}}{s_d} = \frac{t}{\sqrt{n}}$$

**【实验】** 全参 vs LoRA：$d_z = 3.45/\sqrt{200} = 0.24$。

按惯例 0.2 小 / 0.5 中 / 0.8 大 —— **0.24 属于"小效应"**。

这在数字上印证了那个工程判断：差异真实存在（p 过校正），但幅度小
（占总训练收益的 1.1%），**不足以支撑"必须用全参"**。
「统计显著但效应量小」是这个结论的准确表述。

### 10.5 最小可检测效应（MDE）：为什么扩样本后结论会翻转

在 80% 功效、双侧 α=0.05 下，能可靠检出的最小差异约为：

$$\text{MDE} \approx 2.80 \times \frac{s_d}{\sqrt{n}}$$

代入实测 $s_d \approx 0.4$：

| n | MDE | 真实差 0.34 落在哪 |
|---|---|---|
| 6 | ≈ **0.46** | **盲区内** → 测不出，判"无差异" |
| 200 | ≈ **0.079** | 远超阈值 → 显著检出 |

**这就是结论翻转的全部机制**：真实差距 0.34 一直存在，只是 n=6 的分辨力是 0.46，
看不见它。所以小样本给出的从来不是"差异不存在"，而是**"我的尺子量不到这么细"**。

反过来用：**做实验前先算 MDE**。如果关心的差异量级低于 MDE，那这次实验注定得不出结论，
应该先加样本而不是先跑。

### 10.6 置信区间比 p 值信息量大

$$\bar{d} \pm t_{\alpha/2,\,n-1}\cdot \frac{s_d}{\sqrt{n}}$$

全参 vs LoRA：$0.34 \pm 1.97 \times 0.4/\sqrt{200} \approx [0.28,\ 0.40]$。

区间同时给出**方向、幅度和精度**——上界 0.40 相对总收益 30.19 仍然很小，
「即使按最乐观估计，全参的优势也只有 1.3%」。这比"p<0.05"有用得多。

### 10.7 【实验】训练 loss 不能预测评测排名

LR 扫描 4 个点，**loss 曲线最平稳、降幅最大的 5e-5 在评测上显著更差；
曲线最不稳（尖峰到 0.217）的 5e-4 评测最好。**

原因回到第 1.1 节：扩散训练每步随机采 $t$ 和 $\epsilon$，单步 loss 的样本间标准差
比整体下降幅度大一个数量级（实测 last100 stdev 0.029 vs 窗口差 0.003）。

**推论**：
- 引用"首步 X / 末步 Y"站不住（单步极差 0.17）
- 窗口均值是唯一可比口径，但跨配置比较仍不可靠
- **选超参必须看留出集评测**

若要让 loss 可比，得固定 $t$ 与噪声做**确定性验证损失**（固定一批
$(t,\epsilon)$ 复用）——本项目没做，直接用留出集评测代替了。

## 11. 高频追问速答

**Q：为什么不直接用 IDM-VTON 换装？**
它需要 parsing / densepose / openpose / agnostic mask 四套前置产物。VITON 数据集预先算好了，
真实帧要现算——四级串联即使每级 95% 也只剩 81%，而且失败是**静默的**（产出看起来合理但错的 mask）。
它还接不了文字指令、做不了字幕与多参考。所以是「专家 → 通用骨干」的蒸馏。

**Q：为什么不直接用 GPT Image 2？**
外部付费 API：成本延迟不可控、有限流、权重不可微调、数据要出域。

**Q：你做的是知识蒸馏吗？**
不是 logits 层面的知识蒸馏，是**数据层面的伪标注蒸馏**。两个模型架构与输出空间完全不同，
无法对齐 logits。

**Q：全参和 LoRA 你选哪个？**
域内 200 样本下全参在 MAD 上显著更优（t=3.45），但 LoRA 拿到 **98.9%** 的收益，
可训参数只有 1/173、产物 226MB vs 40.86GB。**工程上我会选 LoRA**，除非目标是分布外鲁棒性——
业务域 3 张参考图时只有全参不崩。

**Q：为什么全参必须 ZeRO-3？**
DDP 单副本静态约 282GiB（权重 54 + fp32 梯度 76 + AdamW 152），80GB 卡装不下，
且多卡 DDP 只是多份复制。ZeRO-3 把 P/G/O 三者分到 8 卡，实测峰值 74.8GB。

**Q：6 个样本能得出结论吗？**
不能得出精细排名，只能得出"分辨不出"。而且我后来扩到 200 样本，
**结论确实被推翻了**（方向反转且显著）。这正说明小样本的"无差异"不等于"无差别"。

**Q：为什么用配对检验？**
所有模型跑同一批样本，配对能消掉样本难度这个最大方差源。实测配对后 sd 0.4 vs 独立 1.3–1.9。

**Q：MAD 具体怎么算的？为什么用 L1 不用 MSE？**
两图转 ITU-R 601-2 灰度后逐像素绝对差取均值，尺度 0–255。用 L1 因为：保持灰阶原单位可解释；
MSE 会被服装区域那一小块必然的大偏差主导；L1 对"大面积轻改"与"小面积剧改"惩罚更均衡，
而这正是我要区分的两种失效。

**Q：为什么转灰度算，不在 RGB 上算？**
为了把**结构和颜色拆成两个正交指标**。灰度 MAD 管"哪些像素动了"，颜色交给 H-S 直方图。
RGB 上算会把两种变化混在一个数里，出问题无法归因。

**Q：为什么不用 SSIM / LPIPS / FID / CLIP-score？**
我测的不是"生成质量"而是"改动是否局部且正确"。SSIM 会把**该改的地方**一律记为结构损失；
LPIPS 引入另一个网络的偏好；**FID 是分布级、需要上万样本且无法逐样本出分**——
逐样本出分是配对检验的前提，用 FID 就做不了显著性检验；CLIP-score 下**整幕重绘也能拿高分**，
恰好对我要抓的失效模式免疫。

**Q：直方图为什么只用 H、S 丢掉 V？**
V（明度）已经被 MAD 覆盖了。带上 V 就是重复测量，两个指标会同向共动，失去互补性。

**Q：你的指标有什么盲点？**
MAD 测不到同明度换色，也会被全局亮度偏移虚高；H-S 直方图**完全没有空间信息**，
颜色搬到背景上指标不变。所以两者必须一起看，并配差分热力图做人眼交叉验证。

**Q：多重比较校正做了吗？**
这是我要主动说的一点。LR 扫描是 4 配置 × 3 指标 ≈ 12 次检验，α=0.05 下期望 0.6 个假阳性。
Bonferroni 收到 0.0042、t 临界升到 2.88 后：全参 MAD 优势 t=3.45 **仍然成立**，
但 LoRA 的色彩优势 t=2.78 **过不了**，只能算提示性证据。

**Q：效应量多大？**
配对 Cohen's $d_z = t/\sqrt{n} = 3.45/\sqrt{200} = 0.24$，属于**小效应**。
所以准确表述是「统计显著但效应量小」——差异真实，但只占总训练收益 1.1%，
不足以推翻 LoRA 选型。

**Q：你的差值满足 t 检验的正态假设吗？**
**不满足，我实测过**：n=200 上偏度 −2.70、超额峰度 +26.99、
Shapiro-Wilk p=4.4×10⁻¹⁹，严重重尾。但结论仍成立，因为
①CLT 保护的是均值的抽样分布而非 $d_i$ 本身；
②换成不假设分布的 **Wilcoxon 符号秩检验交叉验证，p<0.00001、同向**，
比 t 检验更强。Wilcoxon 对离群稳健，所以结论不是被那个 −11.35 的离群样本驱动的。

**Q：那 n=6 时是不是该用 Wilcoxon？**
换了也没用——我在那 6 条上实际跑过：t 检验 p=0.650、Wilcoxon p=0.688，
**两种方法都是"分辨不出"**。所以 n=6 的问题是**纯粹的功效不足**
（MDE 0.46 > 真实效应 0.34），不是检验方法选错。
更有意思的是，n=6 上 Shapiro-Wilk 还"不拒绝正态"（p=0.54）——
**正态性检验在小样本下同样没功效**，所以那时连"能不能用这个检验"都判断不了。

**Q：为什么样本量从 6 加到 200 结论会翻转？**
不是差异变了，是尺子变细了。80% 功效下 MDE ≈ $2.80 s_d/\sqrt{n}$，
$s_d\approx0.4$ 时 n=6 的 MDE 是 0.46、n=200 是 0.079。真实差距 0.34 一直在，
只是落在 n=6 的盲区里。**小样本的"无差异"永远只意味着"量不到"。**

**Q：怎么保证是公平对比？**
三层：①**split 级隔离**——训练用 VITON-HD train、评测用 test，人物与服装本体都不重叠，
比随机切分更干净；②固定 seed 抽样，**所有模型评同一批样本**（配对检验的前提）；
③推理配置全固定（steps 40 / cfg 4.0 / 768×1024 / seed 0），prompt 用训练同一 builder
同一参数重建。**唯一自变量是模型权重。**

**Q：训练数据有泄漏风险吗？**
没有。隔离在 split 级别而非随机切分——VITON-HD 的 train/test 本身人物与服装不重叠，
所以不存在"同一个人换个配对出现在测试集"这类泄漏。

**Q：你怎么知道 teacher 是对的？**
不知道它绝对正确——它就是天花板。`MAD vs teacher` 衡量"像不像 teacher"。
所以我同时看业务域（有 GPT 作参照）和肉眼检查，不只依赖单一指标。

**Q：训练 loss 降了多少？**
窗口均值 0.0409 → 0.0311（−23.7%）。但我要强调**这个数不能用来选模型**——
last100 单步 stdev 0.029 比整体降幅还大，LR 扫描里 loss 最好看的配置评测反而最差。

**Q：为什么数据翻倍没效果？**
b2 补的是**配对多样性**（同一批人物×服装重新搭配），人物图、服装图、prompt 模板、
类目覆盖一个没变。而瓶颈正是这些维度的坍缩。组合数上限 1.36 亿，
但视觉素材上限就是那 11,647 张。

**Q：「波动收窄 4.9×」是什么？**
是**单样本 MAD 的标准差**（n=200）：base 20.56 → 全参 4.24，比值 4.85。
base 时好时坏（有的几乎不动、有的整幕重绘），训练后变得一致。
**这是视频管线的关键指标**——一条视频只要崩一帧就废了，
决定可用性的是最坏情况和一致性，不是平均分。所以训练收益有两层：
均值 38.95→8.76 是准确性，波动收窄 4.9× 是可靠性。

**Q：训练用了什么超参？**
AdamW（wd 0.01）、ConstantLR、bf16、grad_accum=1、GC 开、`max_pixels=1048576`、
1 epoch、8 卡有效 batch 8、1427 步。**LR 是唯一按方法区分的**：全参 1e-5、LoRA 1e-4。
框架 DiffSynth-Studio + Accelerate + DeepSpeed，torch 2.6.0+cu124 / deepspeed 0.19.5。

**Q：为什么用 AdamW 不用 Adam？**
AdamW 把 weight decay 从梯度里解耦。Adam 的 L2 正则会被自适应学习率缩放，
等效正则强度失控。显存账里的「×8」就是 m、v 各 4 字节 fp32。

**Q：训练花了多久？显存多少？**
全参 1427 步 × 5.87 s/it = 端到端 **2h22m**，峰值 **74.8GB/80GB（91.7%）**，
util 94.5%，功耗均值 603W。LoRA 同步数 4.60 s/it = **1h49m**，显存 **68.4GB**。
数据翻倍那次 2854 步、4h41m，**显存和单步速度都不变**。

**Q：为什么 LoRA 比全参快 22%？**
四条：无 ZeRO-3 逐层 all-gather；`optimizer.step` 只更新 118M 而非 20B；
无 fp32 master 权重同步；DDP 只 all-reduce 118M 梯度（~0.47GiB）。

**Q：为什么全参 ZeRO-3 显存（74.8GB）比 LoRA DDP（68.4GB）还高？**
反直觉但拆开就清楚：LoRA 虽每卡复制整模 56.7GiB，但只为 118M 付优化器（1.6GiB）；
全参即便分片，fp32 master + AdamW m/v 仍是 30.7GiB/卡，加上 all-gather 瞬态和更大激活反超。
所以 ZeRO-3 的意义不是"更省"，而是**"让全参成为可能"**——纯 DDP 要 245GiB，必 OOM。

**Q：为什么步数是 1427 不是 1426？**
$11415/8=1426.875$，分布式 sampler 不 drop_last、向上 pad 到卡数整数倍 →
11 416 样本 → 每 rank 1427 步。

**Q：产物有多大？**
全参 DiT ckpt **40.86GB**（1933 tensor，DiT-only 不能直接加载）；
LoRA adapter 只有 **226MB**，差 180×。两者 fuse 后的完整目录都是 ~54GB。
合并机制不同：LoRA 是加法 $W+\frac{\alpha}{r}BA$，全参是替换 $W \leftarrow W_{\text{sft}}$。

**Q：跑 2 个 epoch 会更好吗？**
三层：调度层无碍（ConstantLR 不绑 epoch）；loss 层已近平台（末 4 窗口 0.0318→0.0311）；
**风险层反而更可能有害**——参数/数据比 20.43B/11415 ≈ 1.8M 参数每样本，
第二遍重喂同一批唯一图会抬高记忆化风险，而且没有 val loss 判不出膝点。
瓶颈是数据多样性，不是 epoch。

**Q：DiffSynth-Studio 是什么？你改了它吗？**
ModelScope 的开源 diffusion 训练/推理框架，提供 pipeline 抽象和
Accelerate+DeepSpeed 集成。**我没改它的训练循环**——读源码到能指出
`runner.py:66` 把 scheduler 写死成 `ConstantLR`，但我的工作是数据链路、
对照实验和评测协议。用现成框架是因为多图条件编辑的实现细节（条件图入序列、
`zero_cond_t`、多图 RoPE）极易在静默处写错。

**Q：为什么要 NVLink？**
ZeRO-3 每层前向都要 all-gather 参数、反向再来一次，通信量很大。
走 PCIe 会明显掉速，NVLink P2P 是这个配置能跑到 94% util 的前提。

**Q：显存怎么算的？**
bf16 权重 = 参数量 × 2B；fp32 梯度 = 可训参数 × 4B；AdamW = 可训参数 × 8B（m+v）。
ZeRO-3 下三者各除以卡数，再加激活（GC 压着）。口算：bf16 下「参数量(B) × 2 ≈ GiB」。

**Q：你用了 CPU offload 吗？**
要分两侧。**训练侧准备了但没启用**——8 卡 ZeRO-3 实测 74.8/80GB 够用，
`offload_optimizer_device: none`；只在 4 卡 fallback 里配了 ZeRO-2 + optimizer offload。
**推理评测侧是常态开着的**，因为评测跑在共享卡上，模型三件套 bf16 共 57.7GB 拿不到整卡。

**Q：显存够为什么不开 offload？**
它是救命手段不是优化手段。优化器状态搬到 CPU 后每步都要走 PCIe 来回 + 在 CPU 上跑 Adam，
通常慢 2–4 倍。显存够时开它纯亏。

**Q：为什么推理侧开 offload 几乎不损速度？**
扩散 pipeline 阶段严格顺序：TE 编码完就不再需要 → DiT 去噪（占绝大部分时间）→ VAE 只在最后解码。
三者从不需要同时在显存里，所以组件搬运只发生在**阶段切换**时，
**不在去噪循环内部**。这和训练侧每步都搬完全不同。

**Q：ZeRO-3 存 checkpoint 有什么坑？**
默认存出的是分片，得跑 `zero_to_fp32.py` 才能用。本项目开了
`zero3_save_16bit_model: true`，存盘时 all-gather 回完整 bf16 权重，
才拿到那个 1933 tensor 的 DiT 文件。另外 `zero3_init_flag: true` 也必须开——
否则每卡要先完整实例化 20.43B 再分片，**光 init 就 OOM**。

**Q：数据量翻倍要不要加显存？**
不要。ZeRO-3 占用由参数量和 batch 决定，与样本总数无关。翻倍只让步数翻倍，
实测显存 74.8GB → 74.8GB。

**Q：`zero_cond_t` 是什么？**
条件图 token 在时间步上置零——它们是干净参考，不参与加噪轨迹。
Edit-2511 强制要求，不开会训崩。

**Q：为什么 LoRA 用 1e-4 而全参用 1e-5？**
全参直接改预训练权重，大步长会破坏已有能力；LoRA 改的是零初始化的增量，
要从 0 长到有效幅度，需要更大步长。所以**loss 下降速度不能跨方法比绝对值**。

**Q：为什么 bf16 不用 fp16？**
bf16 指数位 8（与 fp32 同）动态范围宽，不需要 loss scaling，训练更稳。

**Q：业务域失效的根因？**
**训练-推理输入配置不一致**：训练固定「源帧 + 1 张商品图」（2 图），
生产给 3 张商品图（4 图）。仅把参考图降到 1 张，连**未经训练的底座**都从整幕重绘
恢复为局部编辑（MAD 72.8 → 32.5）。prompt 只差 90 字符，解释不了这个量级。
机制上是 3D RoPE 的第一个轴（图序号）用到了训练未覆盖的取值。

**Q：这个模型能上线吗？**
现在不能。三处缺口：多参考图会崩（已定位主因）、商品颜色保真不足、字幕不会重写。
而且训练数据是 CC BY-NC 的公开研究数据集，产出只能用于方法验证，
落地需换成自有数据重训。

**Q：下一步怎么做？**
P0 是多参考训练数据（训练时随机化 `n_product_refs ∈ {1,2,3}`，且指令声明的张数必须与
实际输入一致）；其次是用真实帧 + GPT 输出作第二 teacher，同时解决字幕与颜色保真——
但必须在指令里显式区分两个 teacher 的约定，否则模型学成随机二选一。

## 12. 最容易答错的陷阱

| 陷阱 | 正确说法 |
|---|---|
| 「SFT 就是 next-token 预测」 | 这里是扩散回归损失，SFT 只是"有监督微调"的泛称 |
| 「loss 降了说明模型更好」 | 扩散 loss 噪声主导，实测 loss 最好看的配置评测最差 |
| 「无显著差异 = 没有差异」 | 只是**分辨不出**；扩到 200 样本后结论被推翻 |
| 「统计显著 = 值得采用」 | 全参显著更优，但 $d_z=0.24$ 是小效应，只占总收益 1.1% |
| 「跑了 t 检验就够了」 | 12 次检验必须校正；LoRA 的色彩优势过不了 Bonferroni |
| 「换 Wilcoxon 就能救小样本」 | 实测 n=6 上 t 与 Wilcoxon 结论相同；救不了功效不足 |
| 「t 检验通过说明差值正态」 | 实测严重重尾（SW p=4e-19）；结论靠 Wilcoxon 交叉验证才稳 |
| 「MAD 低就是好」 | 无 GT 时低 MAD 可能是**欠编辑**（该改的没改） |
| 「MAD 能测颜色」 | 灰度指标，同明度换色几乎测不到，得靠 H-S 直方图 |
| 「直方图相关高就对了」 | 它**没有空间信息**，颜色搬到背景上分数不变 |
| 「LoRA 省显存」 | 省的是优化器状态；DDP 下**整模仍每卡一份** |
| 「数据越多越好」 | 多样性不变时堆数量收益为零（实测） |
| 「换个分辨率没影响」 | `use_dynamic_shifting` 让噪声 schedule 随 token 数变，分辨率同时改了噪声分布 |
| 「这套能直接上线」 | 数据是 CC BY-NC，只能验证方法；且多参考图仍会崩 |
| 「我搭了训练框架」 | 框架是 DiffSynth-Studio 的；我做的是数据、对照实验与评测 |
